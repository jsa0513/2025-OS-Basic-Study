# Chap15-08 : 파일 시스템 내부구조_NFS
LAN(또는 WAN)을 거쳐 원격 파일에 접근하기 위한 소프트웨어 시스템의 구현과 명세

## 개요
* 서로 연결된 워크스테이션의 집합을 독립적인 파일 시스템을 가진 독립적인 기계들의 집합으로 간주
* 시스템들 사이에서 일정 수준의 공유를 투명하게 허용
  * 사용자가 접근 방식을 몰라도 됨 (로컬 디스크처럼 동작)
* 클라이언트 서버 관계 기반
  * 한 시스템은 동시에 클라이언트이자 서버일 수 있음
* 원격 파일 시스템의 공유는 클라이언트에게만 영향을 줌

특정 시스템 M1이 원격 디렉터리에 접근하는 과정
1. M1이 마운트 명령 수행 -> 원격 디렉터리를 로컬 파일 시스템의 디렉터리 상에 마운트
2. 마운트된 디렉터리가 로컬 파일 시스템의 하부 트리처럼 보임 (기존 하부 트리를 대체)
3. 로컬 디렉터리가 새로 마운트된 디렉터리의 루트의 이름이 됨

**그림 (b)**
* 그림 (a)에서 연속 마운트
* U:/usr/local/dir1에 S2:/usr/dir2 마운트

### 연속 마운트
* 한 파일 시스템이 원격 마운트된 파일 시스템에 다시 마운트되는 것
* *이행성(transitivity)* 특성을 갖지 않음
* 원격 파일 시스템을 마운트하더라도, 해당 원격 파일 시스템에 이미 마운트되어 있던 다른 파일 시스템에는 접근 불가능

## 마운트 프로토콜
서버 <-> 클라이언트 사이의 초기 논리적 연결을 생성

1. 클라이언트가 서버에게 원격 디렉터리 마운트 요구
2. 서버는 수출 리스트로부터 해당 클라이언트가 접근 가능한 디렉터리인지 확인
3. 허용된 요구일 시, 키(key)로 사용할 파일 핸들 반환
-	파일 핸들은 파일 시스템 식별자와 inode 번호로 구성
4.	서버는 또한 클라이언트 시스템과 각 시스템에 현재 마운트 된 디렉터리 리스트 유지 (관리 목적)


## NFS 프로토콜

### Stateful vs Stateless
**Stateful**
* 서버가 클라이언트의 상태 보존
* 클라이언트 상태를 가지므로 용량 한계 O
> 로그인 유지
>
> 쿠키 저장
>
> 세션 메모리 유지

**Stateless**
* 서버가 클라이언트의 상태 보존 X
* 요청 -> 응답만 수행
* 대량의 트래픽이 발생해 서버 확장이 필요할 때에도 대처가 쉬움
