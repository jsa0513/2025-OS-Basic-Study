# Chap14-04 : 파일 시스템 구현_할당 방법
파일들을 어떻게 저장장치 공간에 배치할 것인지?

-> 디스크 공간을 효율적으로 사용하고, 파일들을 빨리 접근할 수 있도록

저장장치 공간 할당 방법: 연속, 연결, 색인(index) 기법

## 연속 할당
각 파일이 저장장치 내에서 연속적인 공간을 차지하도록

-> 논리적으로 근접한 블록이 물리적으로도 근접하다면, 디스크 탐색의 횟수를 최소화

첫 번째 블록의 주소와 (블록 단위의) 길이만 있으면 됨

-> n 블록 길이의 파일이 블록 b에서 시작한다면, b부터 b+n-1까지를 차지

![image](https://github.com/user-attachments/assets/7c8a3e3c-4c47-4850-9fd3-875dcc6c2a68)

### 장점
* 순차 접근, 직접 접근 모두 지원 가능

### 단점
* 새로운 파일을 위한 가용 공간을 찾을 때 문제 발생
  * 실행 단계에서 공간을 할당하는 동적 공간 할당 문제
  * 파일의 크기나 위치가 고정되어 있지 않아, 가용 공간 관리와 관련된 문제가 자주 발생
  * 일반적으로 최초, 최적 적합 적용(최악 적합보다 효율적)
  * 외부 단편화 문제 -> 주기적 밀집 작업으로 해결, 많은 시간과 비용 소모
* 실행 과정에서 만들어질 파일의 크기를 예측하기 힘듦
  * 너무 작은 공간을 예약하면 파일이 커질 수 없음
  * 필요한 공간을 지나치게 크게 추정하면 공간의 낭비(내부 단편화)
  * 어느 정도의 연속된 공간만 초기에 할당하고, 추후 n개의 연속된 공간을 단위로 할당하는 방식 사용 가능

## 연결 할당
연속 할당의 문제점을 해결한 기법

저장장치 블록을 연결 리스트 형태로 저장 -> 블록들이 장치 내에 흩어져 저장 가능

디렉터리는 파일의 첫 번째와 마지막 블록에 대한 포인터를 가짐

![image](https://github.com/user-attachments/assets/584f9297-edc0-4865-9ce9-602758ad901b)

각 블록은 다음 블록을 가리키는 포인터를 포함

-> 사용자는 (한 블록의 크기 - 포인터가 차지하는 영역) 만큼 사용 가능

새 파일 생성 시
1. 디렉터리 내에 새로운 항목(entry) 생성
2. 각 디렉터리 항목은 파일의 첫 블록에 대한 포인터를 가짐 -> 처음에는 null 값으로 초기화, 크기 필드 0
3. 파일 쓰기가 일어나면 가용 블록을 할당 받아 쓰기를 수행 후, 파일의 끝에 포인터를 이용해 연결

### 장점
* 외부 단편화 X
* 모든 블록은 크기가 같기 때문에 아무 가용 블록을 이용하여도 무방
* 파일 생성 시 파일의 크기를 몰라도 됨
* 주기적 밀집화 필요 X

### 단점
* 순차적 접근 파일에만 효과적, 직접 접근 방식에는 매우 비효율적
 * 데이터가 흩어져 있기 때문에 HDD 탐색 필요
* 포인터들을 위한 공간 필요
 * 블록 여러 개를 모아 클러스터를 만들고, 블록이 아닌 클러스터를 할당하면 해결 가능 -> 내부 단편화 증가
* 신뢰성의 문제: 포인터 값을 하나라도 잃어버리게 된다면?
 * 이중 연결 리스트 등 사용해서 해결 가능(오버헤드 발생)
 * 파일 할당 테이블(FAT) 사용

![image](https://github.com/user-attachments/assets/32aa6ee2-8b86-4542-ba32-94a6ecf3d94c)

블록 217, 618, 339가 하나의 파일을 구성

직접 접근 방식 지원

-> 디스크 블록을 직접 탐색하지 않아도 FAT 조회만으로 블록 간 연결 정보를 빠르게 파악 가능

## 색인 할당
모든 포인터들을 하나의 장소 즉, 색인 블록으로 관리

앞서 본 FAT는 테이블 구조 상 체인을 따라가야 하는 오버헤드가 발생하는 반면, 색인 블록은 1번의 참조만으로 접근 가능

색인 블록의 i번째 항목 -> 파일의 i번째 블록

![image](https://github.com/user-attachments/assets/fc11bc56-fd6a-4db5-93e6-472e3b2b8e0d)

색인 블록 항목에서 포인터를 얻어서 블록을 읽음
1. 파일 생성 시 인덱스 블록의 모든 포인터는 null로 설정
2. i번째 블록이 처음 쓰이면, 한 블록을 받아 그 주소를 인덱스 블록의 i번째 항에 기록

### 장점
외부 단편화 없이 직접 접근 지원

### 단점
색인 블록의 크기는 고정 -> 작은 블록으로 구성된 파일이라면 사용되지 않는 주소 공간 낭비

### 해결 방법

#### 연결 기법
파일의 크기가 큰 경우 여러 개의 색인 블록을 연결

#### 다중 수준 색인
연결 기법의 변형으로서 색인 블록을 다단계로 구성

#### 결합 기법
색인 블록의 15개 포인터 유지

크기가 작은 파일의 경우 추가 색인 블록 없이 직접 블록을 가리킴(12개)

나머지 3개의 포인터는 각각 단일, 이중, 삼중 간접 블록

![image](https://github.com/user-attachments/assets/b03a8759-2d64-4a5c-b54b-75d857b8c097)


*직접 색인*과 *다중 수준 색인*을 결합한 구조

## 성능
시스템이 순차 접근/랜덤 접근 중 어떤 방식을 주로 사용하냐에 따라 할당 방법이 달라짐

연속 할당 방식: 순차/직접 접근 모두 가능

연결 할당 방식: 순차 접근 가능
> 직접 접근의 경우 i번째 블록에 액세스 할 때 i번의 블록 읽기가 필요

-> 일부 시스템은 직접 접근을 위해 연속 할당, 순차 접근을 위해 연결 할당 두 가지 모두를 지원

이렇게 여러 할당 방법을 지원하는 경우 파일 생성 시 접근 형태, 최대 크기를 먼저 선언해야 하고, 각 방법들을 모두 제공하는 알고리즘과 자료구조를 유지해야함.

색인 할당 방식은 인덱스 블록이 메모리 내에 상주하는 경우 직접 접근 가능 -> 많은 양의 메모리 필요

-> 일부 시스템은 연속 할당과 색인 할당을 결합하여 작은 파일은 연속 할당 방법을 사용, 큰 파일은 자동으로 색인 할당 방법으로 전환하는 방법을 사용
