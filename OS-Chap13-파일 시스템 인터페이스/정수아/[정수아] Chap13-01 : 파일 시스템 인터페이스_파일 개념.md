# Chap13-01 : 파일 시스템 인터페이스_파일 개념

## 파일
* 저장된 정보에 대한 일관된 논리적 관점을 제공하기 위한 논리적 저장 단위
* 운영체제에 의해 물리 장치들로 사상됨
* 비휘발성

사용자의 편의를 위해 파일에 이름을 부여, 해당 이름으로 파일 참조
> ex) example.c
파일이 생성되면, 부모(프로세스, 사용자, 시스템)로부터 독립
> 네트워크를 통해 복사 가능, 다른 사용자가 편집 가능

## 파일 속성
1. 이름
2. 식별자: 하나의 숫자로 파일 시스템 내에서 파일을 확인, 사람이 읽을 수 없음
3. 유형
4. 위치: 파일이 존재하는 장치, 그 장치 내의 위치에 대한 포인터
5. 크기: 파일의 현재 크기, 최대 허용 가능 크기를 포함
6. 보호: 읽기, 쓰기, 실행 권한 제어
7. 타임스탬프와 사용자 식별: 생성, 최근 변경, 최근 사용 등을 유지

## 파일 연산
1. 파일 생성
2. 파일 열기: 생성과 삭제를 제외한 모든 연산을 하기 전에 반드시 open() 필요, open 콜은 파일 핸들을 반환
3. 파일 쓰기: 쓰기 포인터를 유지
4. 파일 읽기: 읽기 포인터를 유지
* 대부분의 시스템은 하나의 현재 파일 위치 포인터를 유지
5. 파일 안에서의 위치 재설정 = 파일 탐색
6. 파일 삭제: 하드 링크를 허용하는 경우, 실제 파일 내용은 마지막 링크가 삭제될 때까지 삭제되지 않음
7. 파일 절단: 파일의 길이를 제외한 모든 속성을 유지

위의 7개 기본 연산을 결합해 다른 파일 조작 연산 실행 가능

## 하드 링크 vs 심볼릭 링크
하드 링크
* 원본 파일과 동일한 inode를 직접적으로 가리킴
* 원본 파일이 사라지더라도 데이터만 살아 있다면 원본 파일에 접근 가능
* 파일만 참조 가능, 디렉토리는 참조 불가
심볼릭 링크
* 파일/디렉토리 모두 참조 가능
* 원본 파일이 사라지면 해당 데이터에 접근 불가

## 열린 파일 테이블
* 운영체제는 모든 열린 파일에 대한 정보를 갖는 열린 파일 테이블(open-file table)을 유지
* 파일을 연 프로세스 수를 나타내는 열린 계수(open count)를 각 파일마다 가짐
* 프로세스 별 테이블 / 범 시스템 테이블

1. 파일이 사용되기 전에 open() 시스템 콜을 명시적으로 호출
2. open() 연산은 파일 이름을 받아 해당 파일 이름으로 디렉터리를 찾고, 디렉터리 항목을 열린 파일 테이블로 복사
3. 접근 모드 정보를 파일의 권한과 대조
4. 요구된 모드가 허용되면 파일 오픈
5. 열린 파일 테이블의 항목에 대한 포인터를 되돌려 줌
