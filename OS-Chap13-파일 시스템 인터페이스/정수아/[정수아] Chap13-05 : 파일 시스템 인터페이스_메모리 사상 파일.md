# Chap13-05 : 파일 시스템 인터페이스_메모리 사상 파일
파일 시스템 콜을 매번 사용하는 대신 *가상 메모리 기법을 사용한 메모리 참조 방식*을 이용

## 기본 기법
1. 일부 페이지를 디스크에 있는 파일의 블록에 사상
2. 이후에는 read(), write() 등 시스템 콜(오버헤드) X -> 메모리를 통해 파일 조작

메모리 매핑된 파일에 대한 쓰기가 보조저장장치에 반영되는 시점
* 즉각적(동기식)이 아니라 일반적으로 *파일을 닫을 때* 업데이트

### 여러 프로세스가 데이터 공유 시
한 프로세스가 write를 하면 즉시 다른 모든 프로세스에게 반영

-> 보조저장장치에 있는 파일을 공유하는 것이 아닌 *페이지 캐시* 를 공유하기 때문

파일을 공유하는 프로세스들의 page mapping table은 *물리 메모리상의 페이지* 를 가리킴

### 동기식 vs 비동기식
동기식
* 해당 요청의 응답을 받아야 다음 동작을 실행(직렬)
* 작업 순서가 정해져 있으므로, 즉각적으로 이루어지는 것처럼 보임

비동기식
* 요청을 보낸 후 응답과 관계 없이 다음 동작 실행(병렬)
* 나중에 시작된 작업이 먼저 끝날 수 있음

## Windows API에서 공유 메모리
Win32 API에서 메모리 사상 파일을 이용하여 공유 메모리를 생성하는 과정

1. 사상될 파일에 대한 **file mapping** 생성
2. 사상된 파일의 프로세스 가상 주소 공간상의 **뷰(view)** 생성
3. 다른 프로세스는 파일을 오픈한 뒤 사상된 파ㅣㅇㄹ의 뷰를 가상 주소 공간상에 생

1. 생산자 - 공유 메모리 객체 생성
2. 소비자 - 공유 메모리 객체에 대한 사상을 open
