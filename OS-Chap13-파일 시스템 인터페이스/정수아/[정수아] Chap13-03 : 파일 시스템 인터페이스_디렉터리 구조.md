# Chap13-03 : 파일 시스템 인터페이스_디렉터리 구조
디렉터리: 파일 이름 -> 파일 제어 블록으로 바꿔주는 심볼 테이블(symbol table)

### 디렉터리에 대한 연산
1. 파일 찾기
2. 파일 생성
3. 파일 삭제 - 디렉터리 구조에 hole을 남김
4. 디렉터리 나열
5. 파일의 재명명
6. 파일 시스템의 순회 - 여러 디렉터리를 순회해 다니며 파일을 볼 수 있게 해줌

## 1단계 디렉터리
모든 파일이 다 같이 하나의 디렉터리 밑에 존재

파일이 많아지거나, 다수의 사용자가 사용하는 시스템의 경우 제약이 있음
* 각 파일들이 유일한 이름을 가져야 함 -> 두 사용자가 같은 파일명을 사용한다면 문제 발생
* 파일이 증가함에 따라 모든 파일의 이름을 기억하고 유일하게 명명하는 것이 어려움

## 2단계 디렉터리
각 사용자에게 서로 다른 디렉터리를 만들어주는 것 -> 각 사용자는 자신만의 디렉터리(UFD)를 가짐

사용자 접속 시, 시스템은 마스터 파일 디렉터리(MFD)를 탐색 -> MFD는 사용자마다 색인됨

두 사용자가 한 파일을 공유하려면?
1. 서로가 자신의 UFD 접근을 허용
2. 루트(MFD)로부터 leaf(특정 파일)까지의 경로를 정의한 *경로명* 을 사용해 다른 사용자의 디렉터리에 있는 파일을 지칭

### UFD
각 사용자는 본인의 UFD 디렉터리 밑에서만 탐색 가능

UFD 내에서 유일한 파일명을 가짐

삭제 시에도 같은 파일명을 가지는 다른 사용자의 파일 삭제 불가

### MFD
새로운 UFD를 생성, 삭제하는 작업은 시스템 관리자만이 가능

## 트리 구조 디렉터리
높이가 n인 트리를 사용한다면, 각 사용자들이 자신의 *서브디렉터리* 를 만들 수 있게 됨

최상위에 하나의 루트(root) 디렉터리가 존재, 시스템 내의 모든 파일은 고유한 경로명을 가짐

디렉터리의 각 항목은 하나의 비트를 사용 - 일반 파일(0)/디렉터리 파일(1)

각 프로세스는 현재 디렉터리(current directory)를 가짐

**절대 경로명** : 루트(root) ~ 목적 파일까지의 경로

**상대 경로명** : 현재 디렉터리 ~ 목적 파일까지의 경로

파일이 트리 내에서 *유일한 (절대) 경로* 를 가져야 하므로, 두 경로가 같은 파일을 참조할 수 없음 -> 파일 공유 불가능

### 디렉터리의 삭제 문제
디렉터리가 비어있는 경우 문제 X
디렉터리가 *비어있지 않다면* , 시스템에 따라 두 가지 방법 중 하나를 사용
1. 삭제할 수 없음
2. 해당 디렉터리 안에 있는 파일이나 서브디렉터리를 모두 삭제

## 비순환 그래프 디렉터리
디렉터리들이 서브디렉터리, 파일들을 공유할 수 있도록 허용

트리 구조 디렉터리의 제약을 완화 -> 하나의 파일을 *여러 개의 (절대) 경로* 로 참조 가능

디렉터리나 파일을 복사하지 않고, 다양한 경로로 참조함으로서 공유 가능(공유 파일 ≠ 복사본)

공유 파일 구현 방법
1. 링크(link)라 불리는 새로운 디렉터리 항목이자 포인터를 생성
2. 공유하는 디렉터리들이 동일한 내용을 복사해서 가짐 -> 일관성(consistency) 문제

### 공유 파일 삭제 시
1. 누구든지 삭제할 경우 해당 파일을 제거 -> 존재하지 않는 파일을 가리키는 포인터(dangling pointer)들이 존재하게 됨
2. 모든 참조가 지워질 때까지 원본 파일을 보존 -> 파일에 대한 모든 참조 리스트, 즉 참조 계수(count) 저장

## 일반 그래프 디렉터리
순환을 허용하는 그래프 구조

디렉터리 구조에 순환이 발생하면?
1. 파일 검색 시 무한 루프 발생 가능
2. 파일 삭제 시 참조 중이지 않더라도 참조 계수가 0이 아닐 수 있음 -> 가비지 컬렉션 기법 사용
